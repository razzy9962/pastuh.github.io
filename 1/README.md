# Telegram-бот: ручные заявки на доступ

Эта версия **не выставляет счета и не принимает оплату** в Telegram. Старые кнопки «Оплатить» и старые неоплаченные счета отклоняются. Ранее выданный доступ и архив оплат не стираются. Если подтверждение уже принятого Telegram платежа придёт с задержкой после обновления, бот всё равно обработает его один раз, чтобы покупатель не остался без уже оплаченного доступа.

Реквизитов банка, оплаты картой, подтверждения перевода по изображению и инструкций по переводу внутри бота нет. В обычном личном чате можно написать в поддержку. Фото — обычное вложение, оно не переводит заявку в статус оплаченной. [Правила Telegram для продаж цифрового доступа](https://core.telegram.org/bots/payments-stars).

## Обновление существующего сервиса Render

1. Сделайте резервную копию Neon. В том же репозитории замените или добавьте **`bot.py`, `interface.py`, `storage.py`, `render_app.py`** из архива. Лучше одним коммитом.
2. Оставьте **тот же Render-сервис**, ту же Neon-базу, `BOT_TOKEN`, `ADMIN_ID`, `CHANNEL_ID`, `DATABASE_URL` и `WEBHOOK_SECRET`. Новый Blueprint не нужен. Команда запуска остаётся `python render_app.py`. Бот добавит таблицу заявок, не меняя историю оплат и действующие сроки.
3. Дождитесь автодеплоя или нажмите **Manual Deploy → Deploy latest commit**. После успешного запуска в личном чате отправьте `/start`, затем `/admin`. Проверьте, что бот всё ещё администратор закрытой супергруппы и может приглашать и блокировать участников.

Если бэкапы уже настроены в GitHub, их не нужно перенастраивать. Описание резервного копирования: [BACKUP.md](BACKUP.md).

## Рабочий процесс

- **Владелец:** `/admin → Варианты доступа` → создайте или отредактируйте варианты. У варианта есть название, срок и описание, но нет цены. Новый вариант — черновик, пока вы не нажмёте «Опубликовать». Срок уже отправленной заявки сохраняется даже после правки варианта.
- **Подписчик:** `/start → Варианты доступа → выбрать вариант → Запросить доступ → Отправить заявку`. Бот подтверждает «На рассмотрении». В разделе **Мой доступ → Моя заявка** виден последний статус.
- **Владелец:** получаете личное уведомление с Telegram ID и выбранным сроком. Нажмите **Одобрить** или **Отклонить**. Если уведомление не дошло, заявка остаётся в очереди **`/admin → Заявки на доступ`**.
- **Одобрение** даёт или продлевает подписку на срок из заявки и уведомляет участника. Кнопка **Мой доступ → Войти в закрытый чат** даёт ссылку с проверкой Telegram ID. Повторное нажатие «Одобрить» срок не удваивает.
- **Отклонение** также отправляет уведомление и не меняет уже действующую подписку. Повторную заявку можно подать через сутки. Одновременно на одного пользователя может ждать только одна заявка.
- В **Журнале** видны решения по заявкам. Обычная ручная выдача, рассылки, напоминания, экспорт CSV и архив прошлых оплат остаются. Старые скриншоты можно просмотреть в архиве обращений, но новые фото не становятся платёжными обращениями.

Бесплатный Render может засыпать. Обработка заявок, уведомления и проверка окончания доступа продолжаются после запуска. Данные хранятся в Neon.

## Проверка

`python -m pip install -r requirements.txt`, затем `python -m unittest -v`. Для тестов PostgreSQL задайте `TEST_DATABASE_URL` тестовой базы. Перед использованием проверьте со второго аккаунта подачу, одобрение, отклонение и заявку на вход в группу. Живое развертывание в вашем аккаунте не выполнялось.
