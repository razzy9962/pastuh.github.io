# MOEX Terminal + SMC Pro — быстрый старт

Архив содержит готовый исходный код терминала. После распаковки:

```bash
cd codex            # папка с приложением
npm install         # один раз, нужен Node.js 20 или новее
npm run dev         # откройте http://localhost:3000
```

Продакшен-сборка: `npm run build`, затем `npm run start`.

## Интерфейс

Оформление повторяет TradingView: тёмная («чёрная») тема, панель графика с интервалами и SMC Pro,
левый/правый рельсы, «Список наблюдения», нижняя панель инструмента. Тема — `codex/src/app/theme-tradingview.css`.

## Что внутри

- `codex/src/lib/smc.ts` — SMC Pro: Order Blocks (метод LuxAlgo), BOS/CHoCH, FVG, EQH/EQL,
  Premium/Discount, POC и Value Area, уровни PDH/PDL и PWH/PWL, EMA со старших ТФ,
  A+ зоны по конфлюенсу, метки BUY / SELL.
- `codex/src/components/smc-primitive.ts` — отрисовка зон и уровней на графике.
- `codex/src/components/smc-panel.tsx` — панель настроек и дашборд (кнопка «SMC Pro» на графике).
- `codex/src/components/chart-overlays.tsx` — линейка и линия тренда: живой предпросмотр, подписи и цены.
- `codex/src/lib/metrics.ts` — ATR, RSI, наклон EMA 20, 52-недельный диапазон, уровни Фибоначчи
  и дневная сессия (`computeSession`: хай/лоу/открытие/объём текущих суток МСК).
- `codex/src/lib/broker.ts` — виртуальный счёт на 10 000 000 ₽: лонг и шорт с плечом, комиссия, TP/SL.
- `codex/src/components/trading-panel.tsx` — заявка, позиции и окно счёта (вкладка «Торговля»).
  История сделок (до 500) хранится в браузере вместе с балансом и выгружается в CSV из окна счёта;
  метки входов (`moex-marks`, до 40) рисуются на графике стрелками «Покупка / Продажа».
- `codex/src/lib/market.ts` — каталог 254 акций MOEX (весь TQBR) с эшелонами 1/2/3, индексы и валюты,
  а также `sanitizeCandles()` — фильтр битых свечей провайдера.
- `codex/src/lib/marks.ts` — метки сделок на графике: время в мс/с приводится к ближайшему бару.
- `codex/.env.local` — токен Т-Инвест (уже прописан).
- `codex/certs/` — корневой сертификат Russian Trusted CA для API Т-Инвест.

## Данные

Источник — официальный REST API Т-Инвест (токен читается только на сервере), резерв — MOEX ISS
с задержкой до 15 минут. Если не ответил ни один — пустое состояние «Нет данных» и прочерки вместо цен: выдуманных графиков в терминале нет.

## Токен Т-Инвест

Токен уже прописан: `codex/.env.local` (локальный запуск) и `codex/render.yaml`
(переменная `TINKOFF_TOKEN` для Render). После загрузки в приватный репозиторий и создания
Blueprint-сервиса в Render сайт работает без дополнительных настроек.

На обычном VPS просто скопируйте `.env.local` рядом с приложением или задайте
`TINKOFF_TOKEN` в окружении. Токен читается только на сервере и в браузер не попадает.
Если он засветится (например, репозиторий станет публичным) — перевыпустите его в кабинете Т-Инвест.

## Деплой на Render (бесплатный тариф)

1. Загрузите содержимое архива в приватный репозиторий GitHub.
2. В Render: **New → Blueprint**, выберите репозиторий — Render прочитает `codex/render.yaml`
   (rootDir `codex`, build `npm ci && npm run build`, start `npm run start`, health check `/api/health`).

   Если создаёте вручную (**New → Web Service**), Language поставьте **Node** (Render может
   определить Python из-за `requirements.txt` в корне репозитория), Root Directory — `codex`
   (или `moex-terminal/codex`, если корень архива не распакован), Build Command —
   `npm ci --no-audit --no-fund && npm run build`, Start Command — `npm run start`.
   Подробная шпаргалка со всеми полями: `codex/RENDER.md`.
3. Готово. Переменные `TINKOFF_TOKEN`, `NODE_OPTIONS=--max-old-space-size=420`,
   `NEXT_TELEMETRY_DISABLED=1` приходят из blueprint.

Память: сборка идёт с лимитом heap 460 МБ, рантайм — 420 МБ, что укладывается в 512 МБ
бесплатного инстанса. Терминал не тянет тяжёлые зависимости, кеширует данные и отдаёт
готовый HTML — фактическое потребление ~110–140 МБ RSS (видно в `/api/health`).

Без PostgreSQL настройки хранятся в браузере (localStorage) — сайт полностью работоспособен.
Если позже подключите бесплатный Postgres, задайте `DATABASE_URL`, и примените схему командой
`npx drizzle-kit push` — настройки начнут синхронизироваться.

## PostgreSQL (необязательно)

Без `DATABASE_URL` терминал работает с локальной копией настроек в браузере.
С базой: создайте `.env` с `DATABASE_URL`, примените схему `npx drizzle-kit push`,
настройки и рисунки будут сохраняться на сервере (`/api/health` покажет статус).

## Бесплатный Render

Ничего настраивать не нужно, но полезно знать:

- сервис засыпает через 15 минут без посетителей, первый запрос после сна — 30–50 секунд;
- исходящий трафик на Free — 5 ГБ в месяц на всё рабочее пространство, поэтому ответы API
  сжаты gzip, отдают `ETag`/`304`, а в скрытой вкладке опрос останавливается;
- `DATABASE_URL` не нужен: настройки и виртуальный счёт хранятся в браузере;
- `/api/health` всегда отвечает 200 — даже если база недоступна.

Подробности и разбор ошибок деплоя — в `RENDER.md`.
