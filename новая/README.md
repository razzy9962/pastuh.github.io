# Telegram-бот приватной подписки: оплата по реквизитам + проверка по скриншоту

Эта версия бота для закрытого Telegram-канала / супергруппы (`pastuh.github.io/1`) поддерживает **оплату подписки по реквизитам (карта / СБП / номер телефона)** с последующей **отправкой скриншота чека (фото или документа) на проверку администратору**.

Архитектура полностью совместима с вашей текущей базой **Neon PostgreSQL** и сервисом **Render** (`render_app.py`), а также с локальным запуском на SQLite (`bot.py`). Все действующие подписки, история оплат и настройки сохраняются.

---

## Как работает оплата по реквизитам и проверка скриншота

1. **Настройка реквизитов и цен (Владелец):**
   - Откройте `/admin → 💳 Реквизиты оплаты` (или используйте команду `/requisites Текст реквизитов`) и укажите номер карты, телефон СБП, банк и имя получателя.
   - Откройте `/admin → 📋 Варианты доступа` → выберите тариф или создайте новый (`＋ Новый вариант`). В карточке тарифа нажмите **«💰 Цена (₽)»**, чтобы задать стоимость в рублях, и **«✅ Опубликовать»**.
2. **Выбор тарифа и реквизиты (Подписчик):**
   - Подписчик нажимает `/start → 📋 Варианты доступа → выбирает тариф → 💳 Оплатить по реквизитам`.
   - Бот показывает название тарифа, срок доступа, точную сумму к оплате в рублях (`₽`), ваши реквизиты и инструкцию по отправке чека.
3. **Отправка скриншота чека (Подписчик):**
   - После перевода подписчик отправляет **фотографию или документ (PDF/скриншот чека)** прямо в чат с ботом (либо нажимает «📤 Я оплатил — отправить на проверку» и присылает скриншот).
   - Бот автоматически прикрепляет скриншот к заявке `#ID`, переводит её в статус **«На проверке»** (`pending`) и пересылает скриншот администратору.
4. **Проверка скриншота и выдача доступа (Владелец):**
   - Администратор мгновенно получает в личный чат сам скриншот чека и карточку проверки с данными профиля подписчика (`Telegram ID`, `@username`, имя), выбранным тарифом, суммой и кнопками:
     - **«✅ Подтвердить оплату»** — бот автоматически выдаёт или продлевает подписку на срок тарифа, фиксирует оплату в базе (`payments` / `orders`) и в журнале действий (`owner_audit`), а подписчику отправляет уведомление с кнопкой входа в закрытый чат по индивидуально проверяемой ссылке (`ChatJoinRequest` с проверкой Telegram ID).
     - **«✖️ Отклонить»** — заявка отклоняется без изменения уже действующей подписки, подписчик получает уведомление.
   - Все ожидающие скриншоты и заявки также доступны в очереди **`/admin → 📥 Заявки / Скрины`** и **`/admin → 🧾 Архив обращений`**. При открытии заявки в админ-панели бот повторно показывает прикреплённый скриншот чека.

## Обновление существующего сервиса Render

1. Замените файлы **`bot.py`, `interface.py`, `storage.py`, `test_requests.py`, `README.md`** в папке `1/` вашего репозитория `razzy9962/pastuh.github.io`.
2. Оставьте **тот же Render-сервис**, ту же базу **Neon PostgreSQL** и переменные окружения:
   - `BOT_TOKEN`
   - `ADMIN_ID`
   - `CHANNEL_ID`
   - `DATABASE_URL`
   - `WEBHOOK_SECRET`
3. Команда запуска остаётся прежней: `python render_app.py`. При старте бот автоматически создаст таблицы `payment_drafts` и `request_screenshots`, не затрагивая существующие подписки и историю.
4. После деплоя отправьте боту `/start`, затем `/admin` → настройте **«💳 Реквизиты оплаты»** и цены в **«📋 Варианты доступа»**.

## Быстрые команды администратора

- `/admin` — открыть главную панель управления проектом
- `/requisites Банк, номер карты, СБП` — быстро обновить реквизиты для оплаты
- `/plan 30 2500 Доступ на 30 дней` — создать и опубликовать тариф (30 дней, 2500 ₽)
- `/grant 123456789 30` — вручную выдать или продлить подписку пользователю по ID
- `/extend 7` — продлить все активные подписки на 7 дней
- `/rotate_link` — перевыпустить пригласительную ссылку в закрытый чат
